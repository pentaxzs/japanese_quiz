## Priority Issues

### [P0] Theme system fights itself on every page load
RandomThemeProvider.tsx:62 picks one of three palettes with Math.random() and writes 12 CSS vars as INLINE styles on documentElement; it is nested INSIDE next-themes' ThemeProvider (layout.tsx:48-53). Inline style properties outrank class-based rules, so the dark-mode switch cannot change rendered colors. Measured: 10 reloads = navy x2, purple x3, sand x5; with dark preference saved, 5 of 10 reloads rendered the light cream palette; <html> observed carrying both `light` and `dark`; switch reported aria-checked=false while localStorage.theme was "dark". manifest.json declares background_color #f8fafc / theme_color #4f46e5, matching none of the three palettes.
Note: A measured classList as `light` every time; B measured `light dark` together. Both agree the class state is nondeterministic and the toggle does not control color. Race between the two providers.
Fix: delete RandomThemeProvider or demote it to an explicit persisted theme picker with next-themes as sole owner; move palettes behind [data-theme] in CSS, not inline styles; align manifest.json.
Command: /impeccable colorize

### [P0] Accessibility triad — the core interaction has no keyboard path
1. No focus indicator app-wide: button.tsx:8 applies focus-visible:outline-none + ring-ring, but globals.css defines no --ring; focused buttons compute outline:none, boxShadow:none.
2. Reveal surface is a div with mouse/touch handlers only (QuizCard.tsx:54-61) — no role, tabIndex, or key handler; absent from the a11y tree. Keyboard/switch users cannot reveal an answer, though grading buttons remain reachable.
3. layout.tsx:26-27 sets maximumScale:1, userScalable:false — pinch-zoom blocked (WCAG 2.1 SC 1.4.4) in an app for reading small kanji.
Fix: define --ring per theme or drop outline-none; make reveal a real button with aria-expanded responding to Enter/Space; remove maximumScale/userScalable.
Command: /impeccable harden

### [P1] The core loop blanks both moments where learning happens
- Hold-to-reveal removes the answer at grading time (onTouchEnd/onMouseUp reset revealed); long sentence cards force memorizing a full Japanese sentence to self-grade. Hidden answer sits in the DOM, so screen readers announce it unasked.
- A wrong answer produces nothing: instant advance, no correct answer, no reading, no pause. Haptics fire unconditionally — hapticEnabled is read by zero code (verified).
- The end is empty: progress bar stops at 83%, result screen is an outlined trophy + number + one line; the wrong-answer list omits the reading (QuizResult.tsx:48-49), dropping the field most needed for review.
Fix: tap to flip and keep it revealed; on a wrong answer hold ~1.2s showing the correct answer with its reading; fill progress to 100%, count the score up, make 오답만 풀기 the visual primary.
Command: /impeccable shape

### [P2] Two deck cards for one object; tap targets 16-28px
/ and /library both list decks with different designs and feature sets; window.confirm in both with different wording. Measured targets: API-key eye 16x16, word delete 18x18, ⋮ trigger and wrong-note delete 24x24, deck quiz-start 28x28 — all under 44px, with a red trash ~16px from the play button.
